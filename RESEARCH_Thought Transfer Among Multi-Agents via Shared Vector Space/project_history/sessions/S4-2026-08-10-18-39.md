**Lessons learned**:
  - Measure before optimizing. The obvious suspect for slow extraction was `output_hidden_states=True` materializing 1600x more tensors than were read. Removing it saved 13%. The real cost was the bandwidth-bound generate loop at batch size 1, and batching gave 11.2x. One benchmark redirected the whole effort.
  - A safety check is worth more than a correctness argument. `test_batch_of_one_matches_single_prompt` pins the fast path to the slow path; it is the reason the batching rewrite could be trusted without re-verifying every downstream number.
  - Synthetic edge cases catch what real data hides. `mask.sum(1) - 1` counts real tokens instead of locating the last one; it is only wrong when left padding exists, so an equal-length batch would have passed. Hand-checking three synthetic masks found it before it reached the state bank.
  - Test isolation bugs masquerade as code bugs. A module-scoped fixture whose seed was reset to a hardcoded None (not the original 42) left every later test unseeded, which surfaced as an unrelated alias test failing. Restore what was there, not what you assume was there.
  - Colab caches imported modules. `!git pull` does not update a running kernel, and a running process keeps its old code even after the pull — which is why the 4000-prompt job kept its old preset definition mid-run. Restart the runtime after pulling.
  - Numbers outlive the arguments that justified them. 4000 prompts was sized against a 512-dim latent (~2.75M params); after latent_dim dropped to 256 (~1.38M) nobody recomputed it. Assert the *property* (values per parameter) in a test, not the literal number, so a future change cannot silently invalidate it.
  - Decisions logged in a previous session are not decisions the user made. The 4000-prompt corpus was proposed by me in S3, recorded in the log, and then carried into S4 as settled. When the user asked "where did I say that", the honest answer was that they had not. Re-surface inherited decisions before spending an hour on them.
  - Colab's GPU RAM meter shows reserved memory, not allocated. 12.7/15.0 GB looked like an imminent OOM; actual allocation was ~1.5 GB. And a job 173 batches deep with constant shapes will not suddenly OOM.
  - Watch for stale paths after a rename. The bank was renamed m2_baseline → m2_large, and the very next snippet still used the old name. A rename is not complete until every reference follows it.
